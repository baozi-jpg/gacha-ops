# 使用指南

[返回项目首页](../README.md)

GachaOps 用于在 Windows 上统一启动 BetterGI、MAA 和 MaaEnd，安排任务顺序并查看运行结果。游戏内的具体任务仍由各工具执行。

## 快速开始

1. **准备原工具。** 安装需要使用的工具，完成游戏登录和任务配置，确认它们可以独立运行。不使用的工具无需安装。
2. **下载 GachaOps。** 从 [最新版本](https://github.com/baozi-jpg/gacha-ops/releases/latest) 下载 Windows x64 压缩包，完整解压到固定文件夹。不要只取出其中的 EXE，也不要直接在压缩包内运行。
3. **打开程序。** 运行 `GachaOps.exe`。程序会申请管理员权限，请确认下载来源后允许。
4. **添加工具。** 在“设置”→“工具配置”中勾选“使用”，选择“程序位置”，再选好配置或实例。点击“连接检查”。
5. **运行一次。** 退出已打开的原工具，回到“总览”，启用需要执行的任务，点击“运行已启用任务”。首次使用建议观察一次完整运行。

完成首次运行后，再按需设置[每日定时](#每日定时)和[外部通知](#外部通知)。设置会自动保存。

## 准备原工具

GachaOps 使用各工具已有的任务配置。需要修改刷取内容、领取项目或游戏路径时，请在对应工具中设置。

### BetterGI

1. 在 BetterGI 中设置原神启动路径，并确认游戏可以正常启动和登录。
2. 配置要执行的“一条龙”或“配置组”，选好其中的任务。
3. 在 BetterGI 中手动运行一次，确认配置可用。
4. 回到 GachaOps，选择 BetterGI 主程序，在“运行模式”中选择“一条龙”或“配置组”，再选择对应“任务配置”。

新建或修改配置后，如果列表没有更新，点击 GachaOps 的“重新扫描配置”。

### MAA

1. 在模拟器中安装并登录明日方舟，确认 MAA 能连接到正确的模拟器实例。
2. 在 MAA 中选好日常任务，并勾选“开始唤醒”。
3. 在 MAA 的“启动设置”中开启“启动后直接运行”，设置模拟器程序路径。
4. 在“连接设置”中开启“ADB 连接失败时尝试启动模拟器”。
5. 关闭 MAA 和模拟器，再打开 MAA，确认能启动正确实例并开始任务。随后在 GachaOps 中选择 MAA 主程序和“运行配置”。

**MuMu 多开示例：** 如果明日方舟位于 **0 号实例**，在 MAA 的“启动设置”中填写：

| 项目 | 填写内容 |
| --- | --- |
| 模拟器路径 | MuMu 安装目录下的 `nx_main\MuMuManager.exe` |
| 附加命令 | `control -v 0 launch` |

使用其他实例时，将 `0` 换成对应实例编号。这里填写的是 **MAA 的模拟器启动设置**，GachaOps 的“程序位置”仍应选择 MAA 主程序。

其他模拟器的配置请参考 [MAA 连接说明](https://docs.maa.plus/zh-cn/manual/connection.html)和[开始唤醒说明](https://docs.maa.plus/zh-cn/manual/introduction/startup.html)。

### MaaEnd

1. 在 MaaEnd 中设置终末地启动路径，完成登录，并选好日常任务。
2. 确认准备使用的实例能够独立运行。
3. 在 GachaOps 中选择 MaaEnd 主程序及对应的“运行实例”。启动后会自动执行该实例的任务。

### 任务结束后退出工具

建议在各工具中将任务后操作设为“退出所有”，让任务完成后关闭工具、游戏及对应模拟器。若选项名称不同，选择对应的退出设置。

需要 GachaOps 也自动关闭时，在“设置”→“运行设置”中开启“结束退出”。有异常或更新警告时，GachaOps 会保留窗口，方便查看和补做任务。

## 添加工具与运行

### 选择工具和配置

打开“设置”→“工具配置”，对准备使用的工具进行以下设置：

| 工具 | 需要选择 |
| --- | --- |
| BetterGI | 程序位置、运行模式、任务配置 |
| MAA | 程序位置、运行配置 |
| MaaEnd | 程序位置、运行实例 |

点击“选择文件”选择该工具的主程序。列表为空或缺少新配置时，先在原工具中保存配置，再点击“重新扫描配置”。“连接检查”用于检查当前设置，不会启动游戏。

每种工具可添加一项任务，使用设置页选定的一份配置或实例。取消“使用”会隐藏总览中的对应任务，但保留已填写的设置。

### 安排顺序和通道

在“总览”中启用本轮需要执行的任务，拖动任务调整顺序或移动到另一个通道。

- **同一通道：** 按从上到下的顺序运行。
- **不同通道：** 可以同时运行，各自完成后继续下一项。

例如，可将 BetterGI 和 MaaEnd 放在通道 1，将 MAA 放在通道 2。并行前，请先确认电脑能够同时运行对应游戏和模拟器。

开始前退出已打开的 BetterGI、MAA 和 MaaEnd，再点击“运行已启用任务”。运行过程中可在总览查看进度，结束后在“历史”中查看结果。

### 停止与异常处理

| 操作或情况 | 会发生什么 |
| --- | --- |
| 点击“停止后续任务” | 当前任务继续运行，尚未开始的任务不再启动 |
| 关闭 GachaOps | 停止监控，原工具和游戏继续运行 |
| 任务失败或超时 | 不会自动重试；无法安全继续时停止该通道的后续任务，另一通道继续运行 |
| 需要立即停止当前任务 | 到对应原工具中停止，避免误关游戏或模拟器 |

出现异常后，先查看“本轮详情”和原工具的提示。处理完成后，在总览中只启用需要补做的任务，再重新运行。

## 每日定时

### 添加运行时刻

1. 打开“设置”→“定时运行”。
2. 选择或输入小时和分钟，点击“添加时刻”。可添加多个时刻，并分别勾选启用。
3. 打开“启用定时”，确认页面没有提示冲突或“定时不可用”。
4. 回到总览，选好定时运行需要执行的任务和配置。

每个时刻每天触发一次，使用电脑本地时间。不同的定时时刻使用同一套已启用任务，不支持分别指定工作流。

已启用时刻至少间隔一小时，跨午夜也计算。例如，`23:30` 与次日 `00:15` 不能同时启用。提示冲突时，停用其中一个时刻或调整时间。

**启用后无需保持 GachaOps 常驻。关闭窗口不会取消定时。** 如需暂停，请关闭“启用定时”，或取消对应时刻的勾选。

### 运行前需要准备什么

定时时刻到达前，请确保：

- 电脑已开机，当前 Windows 用户已登录，桌面未锁定。
- 前台停留在桌面、任务栏或 GachaOps。可最小化其他应用，避免资源管理器等窗口占据前台。
- 没有正在运行或准备中的 GachaOps 任务，BetterGI、MAA、MaaEnd 也均已退出。

启动前会显示十秒倒计时。点击“取消”只取消本次运行，不影响后续定时。

关机、休眠、锁屏或忙碌时错过的任务不会补跑，也不会自动唤醒电脑。发现未运行时，打开 GachaOps 查看原因，处理后手动补做。

移动或重命名 GachaOps 文件夹后，请重新打开程序，并检查定时状态。准备长期使用时，建议将程序放在固定位置。

## 外部通知

通知是可选功能。可同时使用多个渠道，分别接收运行结果或定时提醒。

### 开启并测试

1. 打开“设置”→“外部通知”，开启“启用通知”。
2. 选择渠道，点击“添加渠道”，填写对应信息并勾选该渠道的“使用”。
3. 点击渠道旁的“测试”，在手机或邮箱中确认收到测试消息。
4. 勾选需要的通知时机。

| 通知时机 | 什么时候发送 |
| --- | --- |
| 定时提醒 | 已启用定时任务开始前 5 分钟 |
| 开始通知 | 定时任务实际开始运行时；手动运行不发送 |
| 结果通知 | 汇总整轮完成情况，包括失败、启动受阻或定时被跳过 |

通知默认关闭。开启后，默认勾选“定时提醒”和“结果通知”，可按需调整。主动取消启动、点击“停止后续任务”或关闭 GachaOps 时，不发送结束通知。

### Bark

适用于 iPhone。

1. 在手机上安装并打开 [Bark](https://github.com/Finb/Bark)，允许它发送通知。
2. 从 Bark 中取得当前设备的推送地址或设备密钥。
3. 在 GachaOps 中填写“服务地址”和“设备密钥”。使用默认服务时，地址为 `https://api.day.app`；自建服务填写自己的地址。
4. 点击“测试”，确认手机收到消息。

服务地址与设备密钥需要分别填写。例如，推送地址中的服务器部分填入“服务地址”，设备对应的 Key 填入“设备密钥”。

### ntfy

1. 在手机的 ntfy 客户端中订阅一个主题，并记下使用的服务地址。
2. 在 GachaOps 中填写**相同的服务地址和订阅主题**。
3. 如果服务要求登录或授权，填写有发布权限的访问令牌；无需授权时可留空。
4. 点击“测试”，确认订阅端收到消息。

公开主题应使用不易被猜到的名称。需要设置访问权限时，参考 [ntfy 官方说明](https://docs.ntfy.sh/publish/#authentication)。

### QQ 邮箱

可使用自己的 QQ 邮箱发送通知，收件人可以是自己或另一个邮箱。

1. 登录 QQ 邮箱，在邮箱设置中开启 SMTP 服务，并生成授权码。
2. 在 GachaOps 中填写 `@qq.com` 发件邮箱、“授权码”和一个“收件邮箱”。
3. **授权码不是 QQ 登录密码。** 请使用邮箱提供的授权码。
4. 点击“测试”，检查收件箱；未收到时也检查垃圾邮件。

GachaOps 已配置发送服务器，无需填写服务器地址或端口。邮件为运行结果的文字摘要，不附带日志。

### QQ 私聊

此渠道需要在 QQ 开放平台配置机器人，准备步骤较多。只需接收提醒时，也可以选择 Bark、ntfy 或 QQ 邮箱。

1. 在 [QQ 开放平台](https://q.qq.com/) 创建机器人，按平台当前要求完成测试成员和使用权限设置。
2. 将机器人的 AppID、AppSecret 填入 GachaOps。在手机 QQ 添加对应机器人为好友，并允许其主动发送消息。
3. 点击 GachaOps 的“绑定”，等待验证码。在 **与该机器人的私聊** 中发送验证码，成功后“用户 OpenID”会自动填写并保存。
4. 点击“测试”，确认在 QQ 私聊中收到测试通知。

OpenID 是机器人识别接收人的标识，不是 QQ 号码。如果已通过同一个机器人取得自己的 OpenID，也可直接填写。绑定期间请及时发送验证码；超时后可重新绑定。

出现无权限、无好友关系或拒收提示时，检查开放平台的测试成员与消息权限，以及 QQ 中的好友和接收设置。本渠道仅用于私聊，不发送群消息。

可参考 [BetterGI 的 QQ 通知配置视频](https://www.bilibili.com/video/BV18Rh46uEVj/)，其中 GachaOps 只使用私聊相关配置。平台权限要求以 [QQ 官方说明](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/overview.html) 为准。

### 暂停通知或移除渠道

关闭“启用通知”可暂停全部通知。取消某个渠道的“使用”只暂停该渠道，填写的信息会保留。

“移除”会清除该渠道在 GachaOps 中保存的信息。若密钥或授权码已经泄露，还应到对应服务中撤销或更换，不能只在 GachaOps 中移除。

## 运行设置

### 自动运行与退出

在“设置”→“运行设置”中可按需开启：

| 选项 | 用途 |
| --- | --- |
| 启动最小化 | 打开 GachaOps 时最小化窗口 |
| 启动运行 | 每次打开 GachaOps 后，自动执行总览中已启用的任务 |
| 结束退出 | 整轮任务顺利完成后关闭 GachaOps；有异常时保留窗口 |
| 工具更新 | 启动任务前检查并更新原工具 |

“启动运行”控制打开程序后的行为，不是 Windows 开机启动。“每日定时”独立生效，不要求同时开启“启动运行”。

### 启动前更新

开启“工具更新”后，GachaOps 会在任务开始前准备工具更新，包括 MAA 官方资源。该选项不会更新 GachaOps 本身。

- 更新期间点击“取消启动”，会取消本次任务。已开始的更新会先完成必要处理，请等待当前更新结束。
- 出现更新或安装检查失败时，按提示检查对应工具，确认工具能够独立启动后再运行。
- 如果需要重新尝试更新检查，可关闭并重新打开 GachaOps。

### 超时保护

在“设置”→“超时保护”中可调整“日志超时”和“运行上限”。

- **日志超时：** 工具长时间没有新日志时，结束本次监控。默认 10 分钟。
- **运行上限：** 单项任务允许的最长运行时间。默认 180 分钟。

频繁超时时，先检查原工具是否卡住、断网或等待操作。确认任务正常但确实耗时较长后，再适当调整。超时不会强制关闭原工具或游戏。

## 常见问题

### 配置列表为空，或找不到新配置

先在原工具中创建并保存配置，确认“程序位置”选择正确，再点击“重新扫描配置”。BetterGI 还需检查“运行模式”是否与配置类型一致。

### 提示工具已在运行

退出已打开的 BetterGI、MAA 和 MaaEnd 后再试。即使某个工具没有在总览中启用，只要它仍在运行，也会阻止整轮启动。

### 定时到了却没有运行

检查“启用定时”、对应时刻的勾选状态和定时状态提示，再检查电脑是否休眠、锁屏、被其他应用占据前台，或仍有原工具未退出。处理后可以手动运行；错过的任务不会自动补跑。

### 收不到通知

先确认“启用通知”、渠道的“使用”和所需通知时机都已勾选，再点击“测试”。

- **Bark：** 检查设备密钥是否属于当前手机，以及手机是否允许 Bark 通知。
- **ntfy：** 检查两端的服务地址、主题是否一致，令牌是否有发布权限。
- **QQ 邮箱：** 检查授权码、收件地址和垃圾邮件。
- **QQ：** 检查机器人好友关系、OpenID 和开放平台权限。

某个通知渠道失败不会停止游戏任务，也不影响其他渠道发送。修正配置后重新测试。

### 任务结束后窗口没有退出

先确认已开启“结束退出”。如果出现未运行任务、执行异常、更新警告或历史保存失败，GachaOps 会保留窗口，请查看提示并处理。

### 如何更新 GachaOps

关闭旧版本，从 [最新版本](https://github.com/baozi-jpg/gacha-ops/releases/latest) 下载压缩包，完整解压到新文件夹后运行。不要只替换一个 EXE。

同一 Windows 用户下，原有设置和历史会继续使用。更换程序位置后，重新打开程序并检查定时状态。

### 如何反馈问题

在“历史”中选择异常记录，点击“选中轮次详情”；查看刚完成的运行时，也可点击“本轮详情”。需要更多信息时，在总览的“技术日志”中复制相关日志。

前往 [Issues](https://github.com/baozi-jpg/gacha-ops/issues)，说明操作步骤、预期结果、实际现象、GachaOps 与原工具版本，并附相关截图或日志。不要附带完整设置文件，分享前遮盖个人信息和通知凭据。

## 数据与隐私

“历史”页保留最近 7 天的运行结果、耗时和异常说明。

设置与记录保存在当前 Windows 用户的 `%LocalAppData%\GachaOps` 文件夹中。需要备份时，先关闭 GachaOps，在资源管理器地址栏粘贴该路径，再复制整个文件夹到自己的备份位置。

设置中可能包含通知密钥、令牌和邮箱信息，请勿公开上传或直接发给他人。更换电脑或 Windows 用户后，QQ 机器人密钥和 QQ 邮箱授权码可能需要重新填写。
