# 使用指南

[返回 README](../README.md)

## 安装与准备

从 [Releases](https://github.com/baozi-jpg/gacha-ops/releases/latest) 下载 Windows x64 压缩包，完整解压后运行 `GachaOps.exe`。

先安装需要的工具，确认它们能够独立完成任务。不使用的工具无需配置。

### BetterGI

设置原神启动路径，配置要使用的一条龙或配置组，并选择需要执行的任务。

### MAA

1. 在模拟器中安装并登录明日方舟，确认 MAA 能正常连接。
2. 选好日常任务，勾选“开始唤醒”。
3. 在“启动设置”中开启“启动后直接运行”，填写模拟器程序路径。
4. 在“连接设置”中开启“ADB 连接失败时尝试启动模拟器”。

使用 MuMu 多开时，必须指定运行明日方舟的实例。以 **0 号实例**为例，在 MAA 的“启动设置”中填写：

- **模拟器路径**：选择 MuMu 安装目录中的 `nx_main\MuMuManager.exe`。
- **附加命令**：填写 `control -v 0 launch`。

使用其他实例时，将 `0` 替换为对应实例编号。配置完成后，关闭 MAA 和模拟器，再打开 MAA，确认能启动正确实例并自动开始任务。

参考：[MAA 自动启动多开模拟器](https://docs.maa.plus/zh-cn/manual/connection.html#自动启动多开模拟器)、[开始唤醒](https://docs.maa.plus/zh-cn/manual/introduction/startup.html)。

### MaaEnd

设置终末地启动路径，勾选需要执行的日常任务。GachaOps 会启动所选实例并自动开始任务。

### 任务结束后的退出设置

推荐将各工具的任务后操作统一设为“退出所有”，完成后关闭工具、游戏及对应模拟器。选项名称不同的工具，开启对应的退出选项。

在 GachaOps 中开启“任务队列结束后退出 GachaOps”，整轮任务顺利完成后自动关闭；有异常或更新警告时保留窗口。

## 添加工具与运行

1. 打开“设置”→“工具配置”，勾选工具的“使用”，选择可执行文件及任务配置或实例。
2. 点击“连接检查”，确认配置可用。BetterGI 会检查所选配置能否读取、解析为 JSON 对象，该检查不会启动游戏。
3. 回到“总览”，启用本次需要运行的任务，拖动调整顺序或分配通道。
4. 点击“运行已启用任务”。

同一通道按顺序执行，两个通道可以同时运行。例如，将 BetterGI 和 MaaEnd 放在通道 1，MAA 放在通道 2。

设置会自动保存。取消工具的“使用”会移除主页卡片，但保留已填写的配置。每种工具支持一项任务，使用设置页选定的单一配置或实例。

任务结束后可查看历史；出现异常时，窗口会恢复并提示需要处理的项目。

## 启动前更新

推荐开启“启动前自动更新工具”，在任务开始前完成工具及 MAA 官方资源的更新准备。

- 每次打开 GachaOps，每个工具最多尝试一次联网更新检查。失败或取消后，本次会话不会重复检查。
- 点击“取消启动”只取消本次任务。已经开始的更新会先安全收尾，期间不会启动新任务。
- 关闭 GachaOps 会停止监控，工具自身的更新可能仍在继续，也不再由 GachaOps 自动关闭。
- 更新超时或无法正常退出时，下次运行前会核验未完成的更新。

配置预检、安装检查或更新恢复失败时，整轮任务不会启动。请根据提示检查后重新运行。

## 每日定时

### 设置时刻

在“设置”→“定时运行”中选择或输入时刻，点击“添加时刻”，再打开“启用定时”。分钟可选择下拉选项，也可直接输入。

- 每个时刻每天触发一次，可单独停用。
- 已启用时刻至少间隔一小时，跨午夜也计算。例如，`23:30` 与 `00:15` 不能同时启用。
- 所有时刻使用触发时主页启用的同一套任务和配置。

冲突时刻可以添加，但不会自动勾选。旧配置存在冲突时，全部定时运行和提前提醒会暂停，取消冲突项后恢复。

### 触发条件

定时按本机时间执行，通过 Windows 任务计划程序触发，无需保持 GachaOps 常驻。**关闭 GachaOps 不会取消定时**，请在设置中关闭总开关或停用对应时刻。

到点时需要：

- 当前用户已登录，桌面未锁定。
- 前台为桌面、任务栏或 GachaOps。
- 没有正在准备或执行的 GachaOps 工作流。
- BetterGI、MAA、MaaEnd 均未运行。

其他应用占据前台时会跳过，包括资源管理器。后台程序不影响；桌宠取得前台焦点时也会阻止本次运行。

前台条件只在进入启动流程前检查。通过后，准备和倒计时期间切换应用不会自动取消任务。

### 取消与跳过

定时运行不受“启动后运行已启用任务”开关影响。启动准备通过后会有十秒倒计时，点击“取消”只取消本次，不影响以后的定时。

倒计时中取消也会保存本轮任务的取消历史。

关机、休眠、未登录或忙碌时错过的任务不会补跑，也不会排队、唤醒电脑或打断正在运行的任务。迟到超过 30 秒及重复触发的请求会跳过。

跳过时，GachaOps 会显示窗口并说明原因，即使通知未开启或发送失败也会显示。锁屏时需解锁后查看。

移动或重命名程序文件夹后，请重新打开 GachaOps，让它修复计划任务路径，并核对设置页状态。显示“定时不可用”时，请检查权限并重新打开程序。

## 外部通知

在“设置”→“外部通知”中点击“添加渠道”，选择 Bark、ntfy、QQ 或 QQ 邮箱。各渠道可以同时使用，每种支持一份配置。

### 配置渠道

| 渠道 | 需要填写 |
| --- | --- |
| Bark | 服务地址，默认 `https://api.day.app`；设备密钥 |
| ntfy | 服务地址，默认 `https://ntfy.sh`；订阅主题；可选访问令牌 |
| QQ | QQ 机器人 AppID、AppSecret、用户 OpenID |
| QQ 邮箱 | `@qq.com` 发件邮箱；QQ 邮箱授权码；一个收件邮箱 |

使用 ntfy 时，手机端需订阅同一服务上的同一主题。受保护主题需要有发布权限的令牌，参考 [ntfy 认证说明](https://docs.ntfy.sh/publish/#authentication)。公开主题请使用难以猜测的名称。

QQ 邮箱需要先在邮箱设置中开启 SMTP 服务并生成授权码，填写授权码而非 QQ 登录密码。程序固定使用 `smtp.qq.com:465` 加密连接并验证证书，发件邮箱也用于登录。收件人可以是自己，不能填写地址列表或抄送。邮件只包含纯文本通知摘要，不附带日志或附件。

QQ 渠道使用官方机器人向自己发送私聊文本通知：

1. 在 [QQ 开放平台](https://q.qq.com/) 创建机器人，获取 AppID 和 AppSecret，填写到 GachaOps。
2. 按开放平台的当前要求配置机器人和测试成员，在手机 QQ 添加机器人好友，并允许机器人主动发送消息。
3. 点击 GachaOps 的“绑定”，等待显示验证码，再用手机 QQ 私聊机器人发送该验证码。成功后自动填写并保存用户 OpenID。绑定最长等待 60 秒，可点击“取消”。OpenID 不是 QQ 号码，需与填写的机器人对应。
4. 开启通知总开关和 QQ 渠道的“使用”，点击“测试”，在手机确认收到“GachaOps · 测试通知”。

可参考 BetterGI 的 [QQ 通知教程](https://www.bilibili.com/video/BV18Rh46uEVj/)，在 GachaOps 中只配置私聊部分。QQ 开放平台的权限和频率限制以 [当前官方说明](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/overview.html) 为准。显示无权限、无好友关系或用户拒收时，按提示检查开放平台或手机 QQ 设置；绑定成功不等于已取得主动推送权限。已在其他软件中绑定同一个机器人的用户 OpenID，也可直接填写。

打开通知总开关和渠道的“使用”开关，点击“测试”，在手机或邮箱收件箱中确认收到通知。服务器接收成功不代表最终送达；未收到邮件时也请检查垃圾邮件。

停用渠道会保留配置；移除渠道会清除其配置与凭据。

### 通知时机

| 通知 | 发送时机 |
| --- | --- |
| 提前提醒 | 已启用的定时时刻前 5 分钟 |
| 开始通知 | 定时启动的工具实际进入运行时 |
| 结果通知 | 运行完成、失败、启动受阻或定时被跳过时 |

通知默认关闭。启用后，开始通知默认关闭，结果通知默认开启，各通知时机可独立选择。

手动运行和打开程序后自动运行不发开始通知，但可发送结果通知。主动取消启动、点击“停止后续任务”或关闭程序时，不发结束通知。

已启用的渠道分别发送，一个渠道失败不影响其他渠道，也不改变任务结果。每次发送最多等待 5 秒，发送失败不会自动重试。

## 停止与异常处理

- **停止后续任务**：当前工具继续运行，尚未开始的任务不再启动。
- **关闭 GachaOps**：停止监控，不强制关闭工具或游戏。
- **工具已在运行**：无论是否选中该工具，整轮启动都会被阻止。退出工具后再运行。
- **任务失败或超时**：不会自动重试。无法安全继续时停止该通道的后续任务，另一通道继续运行。
- **自动退出**：整轮顺利完成后按设置退出；有未运行、失败、执行异常、更新警告或历史保存失败时保留窗口。

首次使用或更新外部工具后，建议观察一次完整运行。

## 历史与数据

历史页可查看最近 7 天的结果、耗时和异常说明。

- “本轮详情”：查看当前会话最近一轮的汇总和日志摘录。
- “选中轮次详情”：查看所选记录所属轮次的已加载记录。旧记录没有轮次标识时，仅显示该条记录。

数据保存在当前 Windows 用户的 `%LocalAppData%\GachaOps`：

| 文件或目录 | 内容 |
| --- | --- |
| `settings.json` | 设置 |
| `runs/history.jsonl` | 运行历史 |
| `scheduled-runs.jsonl` | 定时触发记录 |
| `notifications.jsonl` | 通知发送记录 |
| `crashes/crash.jsonl` | 异常日志 |

Bark 设备密钥和 ntfy 访问令牌虽然在界面中遮罩显示，仍以明文保存在本机设置中。分享设置、日志或截图前，请移除凭据、私密主题及个人信息。

QQ 邮箱授权码使用 Windows 当前用户的 DPAPI 加密保存，发件和收件地址仍保存在设置中。更换电脑或用户后可能需要重新填写授权码；显示“授权码无法解密”时不会使用明文回退。移除渠道会清除本机保存的凭据，但不会撤销邮箱端的授权码，需在 QQ 邮箱中自行撤销。同一 Windows 用户下的恶意程序仍可能访问凭据，请勿分享授权码。

QQ 机器人 AppSecret 同样使用 Windows 当前用户加密保存，AppID 和用户 OpenID 保存在设置中。更换电脑或 Windows 用户后可能需要重新填写 AppSecret。移除渠道不会撤销开放平台的机器人密钥，需在开放平台自行重置。不要分享 AppSecret。
