# GachaOps

将 BetterGI、MAA 和 MaaEnd 集中管理，一键运行多个游戏的日常任务。

选择使用的工具，安排执行顺序，任务结束后统一查看完成情况和需要补做的项目。

GachaOps 是独立的非官方项目，与 BetterGI、MAA、MaaEnd 及相关游戏的开发者或运营方无隶属或授权关系。

## 支持的工具

| 游戏 | 工具 | 使用方式 |
| --- | --- | --- |
| 原神 | [BetterGI](https://github.com/babalae/better-genshin-impact) | 桌面端 |
| 明日方舟 | [MAA](https://github.com/MaaAssistantArknights/MaaAssistantArknights) | 模拟器 |
| 明日方舟：终末地 | [MaaEnd](https://github.com/MaaEnd/MaaEnd) | 桌面端 |

各工具需要自行安装并配置。GachaOps 负责启动、安排顺序和查看结果，游戏中的具体操作由对应工具完成。

只需添加自己使用的工具，不玩的游戏无需配置。

## 主要功能

- **一键运行**：勾选需要的工具，一次启动。
- **按需添加**：在设置中选择使用的工具，主页只显示选中的项目。
- **自由安排顺序**：拖动任务调整顺序，临时不需要的任务可以停用。
- **双通道执行**：同一通道依次运行，两个通道可以同时进行。想全部按顺序执行时，放在同一通道即可。
- **开始前检查**：检查所选任务配置和必要运行设置，避免重复启动已经运行的工具。
- **启动前自动更新**：检查并更新支持的工具及 MAA 官方资源。推荐开启，减少工具在任务开始时自行更新造成的中断。
- **自动开始与退出**：支持打开 GachaOps 后自动运行、启动后最小化，以及全部任务顺利完成后自动退出。
- **异常集中提醒**：运行出现问题时，结束后统一提醒需要检查或补做的项目。
- **运行历史**：查看最近 7 天的运行结果、耗时和异常说明。
- **外部通知**：支持同时启用 Bark 与 ntfy，集中选择通知时机，整轮汇总工具状态、耗时和异常。

## 开始使用

从 [Releases](https://github.com/baozi-jpg/gacha-ops/releases/latest) 下载 Windows x64 压缩包，完整解压后运行 `GachaOps.exe`。不要只复制其中的 EXE；程序需要压缩包内的其他运行库文件。

### 1. 准备工具

下面按 BetterGI、MaaEnd 使用桌面端游戏，MAA 使用模拟器说明。先确认各工具能够独立完成一次任务。

#### BetterGI

设置好原神的启动路径，配置要使用的一条龙或配置组，并选择需要执行的任务。

#### MAA

1. 在模拟器中安装并登录明日方舟，打开 MAA，确认能连接到该模拟器。
2. 选好日常任务，勾选“开始唤醒”，用于启动游戏并进入主界面。
3. 在“启动设置”中开启“启动后直接运行”，填写模拟器程序路径。
4. 在“连接设置”中开启“ADB 连接失败时尝试启动模拟器”，使模拟器关闭时也能自动启动。
5. 使用多开模拟器时，指定运行明日方舟的那个实例：在“附加命令”中填写该实例的启动参数，或将对应实例的快捷方式填入“模拟器路径”。使用快捷方式时，将“附加命令”留空。
6. 关闭 MAA 和模拟器，再打开 MAA，确认能够自动启动正确的模拟器实例并开始任务。

不同模拟器的实例参数不同，请参考 [MAA 模拟器配置说明](https://docs.maa.plus/zh-cn/manual/connection.html#自动启动多开模拟器)。自动进入游戏的设置见 [开始唤醒](https://docs.maa.plus/zh-cn/manual/introduction/startup.html)。

#### MaaEnd

设置好终末地的启动路径，勾选需要执行的日常任务。GachaOps 会启动所选实例并自动开始任务。

各工具完成任务后的游戏退出、模拟器退出或工具退出行为，在对应工具内设置。

### 2. 添加到 GachaOps

打开“设置”的“工具配置”，勾选对应工具的“使用”，选择工具的可执行文件，再选择任务配置或实例。

设置分为“工具配置”“定时运行”“外部通知”“运行设置”“超时保护”五组，可独立展开或折叠。折叠只收起内容，不改变启用状态。

不需要的工具保持未选中即可。取消选择会从主页移除卡片，已填写的工具配置仍会保留。

推荐开启“启动前自动更新工具”，在开始任务前完成更新准备。

更新期间点击“取消启动”会取消本次任务。已启动的工具更新会继续等待完成，确认更新完成后请求本轮更新启动的 BetterGI、MAA 或 MaaEnd 正常退出，不强制结束进程。GachaOps 保留窗口，收尾期间不启动新的任务或更新。MAA 官方资源下载可以直接取消；若已开始写入资源，会先完成安全收尾。关闭 GachaOps 会停止监控，工具自身的更新可能仍在继续，也不再自动关闭工具。更新超时或无法正常退出时保留恢复记录，再次运行前核验未完成的更新。

### 3. 检查与安排

点击“连接检查”，确认选中的工具配置可以使用。该检查不会启动游戏。

回到“总览”，打开本次需要运行的任务开关，拖动调整顺序或分配通道。例如，让 BetterGI 和 MaaEnd 在通道 1 依次运行，MAA 在通道 2 同时运行。

### 4. 开始运行

点击“运行已启用任务”。启动准备完成后，GachaOps 会自动最小化。

任务结束后可在历史中查看结果；出现异常时，窗口会恢复并提示需要处理的项目。

## 使用说明

### 每日定时

在设置的“定时运行”中分别选择或输入小时和分钟，再点击“添加时刻”并打开“启用定时”开关。中间冒号固定，小时为 `0–23`，分钟为 `0–59`，两项均支持一位或两位数字，例如 `8` 和 `5` 会保存为 `08:05`。分钟下拉提供 `00、15、30、45`，也可以输入任意分钟；空值、非法输入和重复时刻会提示且不添加，重复添加不会改变已有项的勾选状态。每项每天触发一次，不是每 15 分钟循环。各项可以单独停用，所有时刻都运行当时主页启用的同一套任务，使用设置页的单一配置。

已勾选时刻之间至少间隔一小时，恰好一小时允许，跨午夜也计算间隔，例如 `23:30` 与 `00:15` 不能同时勾选。冲突时刻可以添加，但保持未勾选；尝试勾选时会提示冲突时刻。旧配置若已有冲突，保留原勾选并暂停全部定时运行及提前提醒，取消冲突项后恢复。间隔一小时不保证上一轮已结束，到点仍有一轮运行或准备中时跳过。

时刻按本机时间执行。GachaOps 使用 Windows 任务计划程序，不需要常驻、托盘或开机自启动。**关闭 GachaOps 不会取消定时**；需要在设置中关闭定时总开关或停用对应时刻。程序只管理带有 GachaOps 标识、属于当前用户的计划任务，停用后保留任务定义。

到点时需要用户已经登录、桌面未锁定，前台为桌面、任务栏或 GachaOps。其他应用占据前台时跳过，包括资源管理器窗口；后台程序不影响，桌宠仅可见或置顶时不影响，取得前台焦点时会阻止本次运行。程序先检查前台，再显示窗口，并保留显示前的阻止原因；更新等启动准备完成后还会复查。既有工具运行检查仍然有效，已有一轮运行或准备中时直接跳过，不排队、不打断。定时运行被跳过时，显示或恢复 GachaOps 窗口并提示原因，不启动该次工具任务，也不自动退出；通知关闭、没有渠道或发送失败时同样显示，发送失败会一并提示。锁屏时不会解锁电脑，窗口需解锁后查看。已有一轮运行时，跳过提示不覆盖其本轮详情，提示处理期间不会因该轮成功完成而自动关闭窗口。

定时入口独立于“启动后运行已启用任务”开关，不使用该开关的倒计时。触发只接受计划时刻起 30 秒内的请求，迟到、时钟切换产生的歧义时刻及同一天同一时刻的重复触发均跳过。关机、休眠或未登录错过后不补跑，不唤醒或解锁电脑。计划任务沿用程序的管理员权限要求，仅在当前用户已登录时运行，不保存 Windows 密码。

通知总开关和提前提醒开关均开启时，会在每个启用时刻前 5 分钟短暂启动通知入口，发送后退出，不显示主窗口或运行工具。新增时刻不足 5 分钟时，已错过的提醒不会补发，到点仍尝试运行；次日正常提前提醒。开始通知仅在定时启动的工具实际进入运行时发送，结果通知覆盖前台占用等定时跳过、启动受阻及本轮结果。通知受本机状态、网络和推送服务影响，不能保证送达；关机或未登录时无法发送本机提醒。

移动或重命名 GachaOps 文件夹后，先重新打开程序，让它修复计划任务中的路径，再核对设置页状态。显示“定时不可用”时，应检查权限并重新打开；不要将勾选状态视为注册成功。失败、执行异常或历史保存失败会保留窗口，成功沿用“任务队列结束后退出”设置。定时触发日志为用户数据目录下的 `scheduled-runs.jsonl`，任务跳过也会写入运行历史。

### 外部通知

在设置的“外部通知”分组中，通过“添加渠道”选择 Bark 或 ntfy，每种可添加一份配置，也可同时使用。每个渠道有独立的“使用”“测试”和“移除”按钮。测试只发给所选渠道，需要同时打开通知总开关和该渠道的“使用”开关。移除会清除该渠道保存的配置与凭据，停用则保留配置。

- Bark：分别填写服务地址（默认 `https://api.day.app`）与设备密钥。旧版完整 Bark 地址会自动拆分迁移，保留自建服务、反向代理前缀和原通知开关，无需重新填写。
- ntfy：填写服务地址（默认 `https://ntfy.sh`）、订阅主题和可选的访问令牌。手机端订阅同一服务上的同一主题。公开可写主题可不填令牌，受保护主题需提供有发布权限的令牌，见 [ntfy 认证说明](https://docs.ntfy.sh/publish/#authentication)。主题使用英文字母、数字、下划线或连字符。公开主题应选择难以猜测的名称。

通知时机在渠道上方集中设置，运行通知会发送给所有已启用渠道。测试显示“服务已接收”后，仍需在手机确认收到。

通知默认关闭。启用后，定时开始通知默认关闭，结果通知默认开启。手动运行和打开后自动运行不发开始通知，自然完成或失败仍按开关发送结果通知。主动取消启动、取消准备或点击“停止后续任务”时不发结束通知，关闭程序也不发结束通知；本地历史与详情照常保留。关闭总开关会保留子选择，且不发送测试或运行通知。提前 5 分钟提醒仅用于已启用的每日定时，与开始通知、结果通知分别控制。

结果通知每轮一次，覆盖启动被阻止、失败、执行异常和完成，主动取消或停止除外。工具任务完成不代表游戏奖励全部领取。各渠道并行发送，分别最多等待 5 秒，不重试。一个渠道失败不阻止另一个渠道发送，也不改变任务结果或原定退出行为。用户数据目录下的 `notifications.jsonl` 按渠道记录通知类型、定时时刻、服务接收或未发送及失败原因；“服务已接收”不代表手机已收到。发送失败同时保存在 `crashes/crash.jsonl`，区分 HTTP 请求错误分类、连接读写、响应解析、超时及服务拒绝，不记录服务地址、设备密钥、访问令牌、订阅主题、通知正文或服务端原文。

在历史页点击“本轮详情”可查看当前会话最近一轮的汇总和日志摘录，即使历史保存失败也可查看。选择历史记录后，点击“选中轮次详情”查看同轮已加载记录。旧记录没有整轮 ID 时仅显示所选记录。历史保存失败、工具失败或执行异常时仍保留窗口。

Bark 设备密钥和 ntfy 访问令牌在界面中遮罩显示，仍随本机设置明文保存。分享设置文件前请移除凭据及私密主题。

### 运行规则

- 支持 Windows x64。
- 设置会自动保存，下次打开后可以继续使用。
- 每种工具支持一项任务，使用设置页选定的配置或实例。
- 点击“停止后续任务”后，当前工具会继续运行，尚未开始的任务不再启动。
- 关闭 GachaOps 不会强制关闭正在运行的工具或游戏。
- 开始前，只要 BetterGI、MAA、MaaEnd 任一工具仍在运行，无论是否勾选，本轮都不会进入启动准备；退出工具后可重新运行。准备完成后的实际启动前会再次检查。
- 本轮任务的配置预检、安装检查或更新恢复失败时，整轮停止并提醒检查配置或安装，其他任务也不会启动。已开始的更新会先安全收尾。
- 每次打开 GachaOps，每个工具最多尝试一次联网更新检查；失败或取消后也不重复检查。重新开始仍会进行本地安全检查，尚未检查过的工具保留首次检查机会。
- 任务失败或超时后不会自动重试；无法安全继续时，会停止该通道的后续任务，另一通道继续运行。
- 首次使用或更新外部工具后，建议观察一次完整运行，确认结果符合预期。

## 从源码构建

需要 Windows x64、PowerShell 和 .NET 10 SDK。克隆仓库后，在仓库根目录运行：

```powershell
dotnet restore GachaOps.slnx --configfile NuGet.Config
dotnet build GachaOps.slnx --configuration Release --no-restore
dotnet run --project tests/GachaOps.Core.Tests/GachaOps.Core.Tests.csproj --configuration Release --no-build
```

仓库中的 `scripts` 脚本使用项目本地 `.dotnet` SDK，主要用于本项目的隔离构建环境。

## 数据与使用风险

设置、运行历史和崩溃日志保存在当前 Windows 用户的 `%LocalAppData%\GachaOps` 中，不会随发行包分发。GachaOps 会按用户配置启动外部工具并访问网络检查更新；使用前请自行确认相关工具及游戏的许可、账号和自动化规则。
