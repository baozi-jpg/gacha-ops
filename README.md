# GachaOps

将 BetterGI、MAA 和 MaaEnd 集中管理，一键运行多个游戏的日常任务。

选择使用的工具，安排执行顺序，任务结束后统一查看完成情况和需要补做的项目。

GachaOps 是独立的非官方项目，与 BetterGI、MAA、MaaEnd 及相关游戏的开发者或运营方无隶属或授权关系。

## 支持的工具

| 游戏 | 工具 | 使用方式 |
| --- | --- | --- |
| 原神 | [BetterGI](https://github.com/babalae/better-genshin-impact) | 桌面端 |
| 明日方舟 | [MAA](https://github.com/MaaAssistantArknights/MaaAssistantArknights) | 模拟器 |
| 明日方舟：终末地 | [MaaEnd](https://github.com/MaaEnd/MaaEnd) | 桌面端 |

各工具需要自行安装并配置。GachaOps 负责启动、安排顺序和查看结果，游戏中的具体操作由对应工具完成。

只需添加自己使用的工具，不玩的游戏无需配置。

## 主要功能

- **一键运行**：勾选需要的工具，一次启动。
- **按需添加**：在设置中选择使用的工具，主页只显示选中的项目。
- **自由安排顺序**：拖动任务调整顺序，临时不需要的任务可以停用。
- **双通道执行**：同一通道依次运行，两个通道可以同时进行。想全部按顺序执行时，放在同一通道即可。
- **开始前检查**：检查所选任务配置和必要运行设置，避免重复启动已经运行的工具。
- **启动前自动更新**：检查并更新支持的工具及 MAA 官方资源。推荐开启，减少工具在任务开始时自行更新造成的中断。
- **自动开始与退出**：支持打开 GachaOps 后自动运行、启动后最小化，以及全部任务顺利完成后自动退出。
- **异常集中提醒**：运行出现问题时，结束后统一提醒需要检查或补做的项目。
- **运行历史**：查看最近 7 天的运行结果、耗时和异常说明。
- **Bark 通知**：独立选择开始与结果通知，整轮汇总工具状态、耗时和异常。

## 开始使用

从 [Releases](https://github.com/baozi-jpg/gacha-ops/releases/latest) 下载 Windows x64 压缩包，完整解压后运行 `GachaOps.exe`。不要只复制其中的 EXE；程序需要压缩包内的其他运行库文件。

### 1. 准备工具

下面按 BetterGI、MaaEnd 使用桌面端游戏，MAA 使用模拟器说明。先确认各工具能够独立完成一次任务。

#### BetterGI

设置好原神的启动路径，配置要使用的一条龙或配置组，并选择需要执行的任务。

#### MAA

1. 在模拟器中安装并登录明日方舟，打开 MAA，确认能连接到该模拟器。
2. 选好日常任务，勾选“开始唤醒”，用于启动游戏并进入主界面。
3. 在“启动设置”中开启“启动后直接运行”，填写模拟器程序路径。
4. 在“连接设置”中开启“ADB 连接失败时尝试启动模拟器”，使模拟器关闭时也能自动启动。
5. 使用多开模拟器时，指定运行明日方舟的那个实例：在“附加命令”中填写该实例的启动参数，或将对应实例的快捷方式填入“模拟器路径”。使用快捷方式时，将“附加命令”留空。
6. 关闭 MAA 和模拟器，再打开 MAA，确认能够自动启动正确的模拟器实例并开始任务。

不同模拟器的实例参数不同，请参考 [MAA 模拟器配置说明](https://docs.maa.plus/zh-cn/manual/connection.html#自动启动多开模拟器)。自动进入游戏的设置见 [开始唤醒](https://docs.maa.plus/zh-cn/manual/introduction/startup.html)。

#### MaaEnd

设置好终末地的启动路径，勾选需要执行的日常任务。GachaOps 会启动所选实例并自动开始任务。

各工具完成任务后的游戏退出、模拟器退出或工具退出行为，在对应工具内设置。

### 2. 添加到 GachaOps

打开“设置”，勾选对应工具的“使用”，选择工具的可执行文件，再选择任务配置或实例。

不需要的工具保持未选中即可。取消选择会从主页移除卡片，已填写的工具配置仍会保留。

推荐开启“启动前自动更新工具”，在开始任务前完成更新准备。

更新期间点击“取消启动”会取消本次任务并停止等待，工具自身的更新可能仍在继续，之后可以关闭 GachaOps。MAA 官方资源下载可以直接取消；若已开始写入资源，会完成安全收尾后再退出。再次运行前会核验未完成的更新。

### 3. 检查与安排

点击“连接检查”，确认选中的工具配置可以使用。该检查不会启动游戏。

回到“总览”，打开本次需要运行的任务开关，拖动调整顺序或分配通道。例如，让 BetterGI 和 MaaEnd 在通道 1 依次运行，MAA 在通道 2 同时运行。

### 4. 开始运行

点击“运行已启用任务”。启动准备完成后，GachaOps 会自动最小化。

任务结束后可在历史中查看结果；出现异常时，窗口会恢复并提示需要处理的项目。

## 使用说明

### Bark 通知

在设置的“通知”分组中启用通知，填写包含设备密钥的完整 Bark 地址，例如 `https://api.day.app/你的设备密钥`，也可使用自建服务地址及反向代理路径。点击“测试通知”后，还需在手机确认收到。

通知默认关闭。启用后，开始通知默认关闭，结果通知默认开启；手动运行和打开后自动运行都使用这些开关。关闭总开关会保留子选择，且不发送测试或运行通知。提前 5 分钟提醒的选择已保存，仅供定时运行使用，本阶段尚未提供调度功能。

结果通知每轮一次，覆盖启动被阻止、失败、执行异常和完成。工具任务完成不代表游戏奖励全部领取。通知发送最多等待 5 秒，不重试；发送失败不改变任务结果或原定退出行为。失败原因保存在本机 `crashes/crash.jsonl`，不包含 Bark 地址、密钥或服务端原文。

在历史页点击“本轮详情”可查看当前会话最近一轮的汇总和日志摘录，即使历史保存失败也可查看。选择历史记录后，点击“选中轮次详情”查看同轮已加载记录。旧记录没有整轮 ID 时仅显示所选记录。历史保存失败、工具失败或执行异常时仍保留窗口。

Bark 地址包含推送凭据，界面隐藏显示，随本机设置保存。分享设置文件前请移除该地址。

### 运行规则

- 支持 Windows x64。
- 设置会自动保存，下次打开后可以继续使用。
- 每种工具支持一项任务，使用设置页选定的配置或实例。
- 点击“停止后续任务”后，当前工具会继续运行，尚未开始的任务不再启动。
- 关闭 GachaOps 不会强制关闭正在运行的工具或游戏。
- 开始前，只要 BetterGI、MAA、MaaEnd 任一工具仍在运行，无论是否勾选，本轮都不会进入启动准备；退出工具后可重新运行。准备完成后的实际启动前会再次检查。
- 本轮任务的配置预检、安装检查或更新恢复失败时，整轮停止并提醒检查配置或安装，其他任务也不会启动。已开始的更新会先安全收尾。
- 每次打开 GachaOps，每个工具最多尝试一次联网更新检查；失败或取消后也不重复检查。重新开始仍会进行本地安全检查，尚未检查过的工具保留首次检查机会。
- 任务失败或超时后不会自动重试；无法安全继续时，会停止该通道的后续任务，另一通道继续运行。
- 首次使用或更新外部工具后，建议观察一次完整运行，确认结果符合预期。

## 从源码构建

需要 Windows x64、PowerShell 和 .NET 10 SDK。克隆仓库后，在仓库根目录运行：

```powershell
dotnet restore GachaOps.slnx --configfile NuGet.Config
dotnet build GachaOps.slnx --configuration Release --no-restore
dotnet run --project tests/GachaOps.Core.Tests/GachaOps.Core.Tests.csproj --configuration Release --no-build
```

仓库中的 `scripts` 脚本使用项目本地 `.dotnet` SDK，主要用于本项目的隔离构建环境。

## 数据与使用风险

设置、运行历史和崩溃日志保存在当前 Windows 用户的 `%LocalAppData%\GachaOps` 中，不会随发行包分发。GachaOps 会按用户配置启动外部工具并访问网络检查更新；使用前请自行确认相关工具及游戏的许可、账号和自动化规则。
